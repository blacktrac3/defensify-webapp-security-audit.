# 🔐 Web Application Security Audit  
### Sample Client Engagement – DEFENSIFY

This repository contains a **sanitized, professional-grade web application security audit** conducted on a deliberately vulnerable public test application.  
The project simulates a **real-world client engagement**, following structured audit methodology and industry best practices.

It demonstrates how **Defensify** approaches web application security assessments — from scoping and reconnaissance to risk analysis and executive-level reporting.

---

## 📌 Project Objective

The objective of this audit was to:

- Identify security vulnerabilities in a web application
- Validate findings through manual testing
- Assess technical and business risk
- Deliver a **clear, actionable, client-ready security report**

This repository is intended for **demonstration and portfolio purposes only**.

---

## 🎯 Target Application

- **Target:** `testphp.vulnweb.com`
- **Type:** Public intentionally vulnerable test application
- **Purpose:** Legal testing and security research
- **Testing Mode:** Non-destructive, proof-of-concept only

No real user data or production systems were involved.

---

## 🧠 Audit Methodology

The audit followed a structured, real-world methodology similar to professional consulting engagements:

1. **Project Scoping & Rules of Engagement**
2. **Reconnaissance & Attack Surface Mapping**
3. **Automated Vulnerability Scanning**
4. **Manual Validation & Exploitation (Safe PoC)**
5. **Risk Analysis & Severity Classification**
6. **Professional Security Reporting**

Detailed methodology is documented separately in the repository.

---

## 🛠 Tools & Techniques Used

- OWASP ZAP
- Nikto
- Nmap
- Manual testing techniques (SQLi, XSS, auth testing)
- OWASP Testing Guide principles

Automated tools were used for coverage; **manual testing was used for validation**.
